## 1. 项目定位

这是专用硬件适配系统，不是通用 ESP32 固件。嵌入式设备负责触摸、画面、声音、连接与状态；桌面程序负责高级映射和管理。Codex 自身决定官方通道上按键事件的含义。

设备端使用原生嵌入式 UI，不运行 React。React 只用于电脑上的管理程序。项目独立于 OpenAI、Work Louder 和 Waveshare，不表示官方认证或支持；协议可能随宿主应用更新而变化。

## 2. 开始之前

请具备阅读终端日志、编译 ESP-IDF 工程、识别串口和恢复开发板的能力。先保存原有固件源码、构建配置和重要设置。不要对不确定的端口执行擦除操作。

本源码版不执行 eFuse 烧写、不要求激活账户、不提供设备绑定加密升级服务。**关闭源码中的安全功能不能撤销芯片已经烧写的 eFuse**。曾启用 Secure Boot 或 Flash Encryption 的开发板，不能假定可直接刷入普通镜像。

先不接电池也可调试。使用能传数据的线，并保留 BOOT 和 USB TO UART 的物理访问空间。

## 4. 硬件与官方资料

目标为 **Waveshare ESP32-S3-Touch-LCD-4B**，480 × 480 四英寸触摸屏。主要硬件为 ESP32-S3、16 MB Flash、8 MB PSRAM、ST7701 显示与 GT911 触摸、AXP2101 电源管理。

[微雪官方 Wiki：手册、示例与硬件资料](https://www.waveshare.net/wiki/ESP32-S3-Touch-LCD-4B)

请从该页面核对实际板卡版本。名称中的 **4B** 不能省略；4、4.3 或其他类似型号不视为兼容。Wiki 同时展示 Arduino 示例，但本项目使用 ESP-IDF，不要将其 Arduino 依赖版本直接替换到本项目。

## 5. 两个 USB 接口

| 板上标识 | 用途 | 电脑端识别依据 |
|---|---|---|
| USB TO UART | 烧录、启动日志、恢复、开发 HIL | CH343 串口；COM 号会变化 |
| USB | 固件实现的原生 USB 通信 | 以实际 HID/CDC 枚举为准 |

两根线都插入，不意味着一定有两个 COM：HID 接口不要求表现为串口。供电成功也不代表数据链路成功。不要在教程中固定使用 COM3 或 COM5。

电脑连接声可能意味着重新枚举，不足以证明主程序崩溃；需要同时检查 UART 的启动日志、复位原因与运行时间。

## 6. 首次使用流程

1. 核对板型，阅读烧录与恢复章节。
2. 自行构建固件，优先通过 USB TO UART 烧录。
3. 确认进入经典界面，BOOT 能打开设置，PWR 可按预设进入待机。
4. 选定 USB 或 BLE 日常连接方式；确认 Codex 不只是发现设备，而是完成通信。
5. 先验证普通点按，再验证 MIC 的按住与松开。
6. 需要高级层和快捷键时，再启动自行构建的管理客户端。
7. 完成基础验证后再连接合适电池、装入外壳。

不要一开始同时修改蓝牙绑定、层路由、图标和电源策略。逐项确认便于识别问题。

## 8. 按键与长按

MIC 的按下和松开是两个事件。长按录音场景必须验证松开事件确实抵达电脑；设备上的按键弹起动画不是电脑停止录音的证据。

旋钮旋转、点按和长按应分开理解。手指移动旋转时不应按静止长按处理。摇杆用于方向/幅度事件，不发键盘轴体声。

BOOT 在正常运行中用于设置/连接操作，**上电时按住 BOOT 仍保留 ROM 下载入口**。不得断开 GPIO0，也不得让其常态被拉成按下。PWR 长按关机属于板载电源控制路径，不能用普通 GUI 黑屏来代替。

## 9. 设置中心第一页

第一页面向连接与日常状态：

- AUTO、USB、BLE、MIX 通信方式；
- BLE 1 / 2 / 3 槽位；
- 蓝牙状态指示、协议连接状态；
- 电池百分比、充电/供电信息；
- 音量滑块；
- 蓝牙开关与重置入口。

选择模式后应观察实际连接结果。MIX 会维持更多通信路径，不应假定与单路径待机具有相同耗电量。重置蓝牙会影响配对，排查时不要把它当成无副作用的刷新按钮。

## 10. 设置中心第二页

第二页包括屏幕亮度、经典摇杆灵敏度、屏保时间、自动关机时间、智能屏保、防误触关机、受保护待机、Arcade 入口和固件版本。

亮度滑块当前分为十档，最低为 10%。最低亮度不等于息屏。翻页使用 **Previous / Next 点击按钮**，不是横向拖动；底部圆点表示当前页。

关机时间按钮和屏保时间按钮是不同配置。文案中的 Off 可能表示“自动关机时间”或某开关的关闭状态，遇到歧义请以邻近功能名称和本章说明区分；不要将历史内部变量 super_standby 当成用户语义。

## 11. 设置中心第三页

第三页控制更深层的电源策略：

- PWR 短按映射：Connected standby 或 Ultra standby；
- Auto ultra：自动进入深待机的时间；
- Ultra touch wake：深待机时是否保留触摸唤醒。

Connected standby 目标是保留通信；Ultra 会主动断开后进入深待机，唤醒后重建连接。开启触摸唤醒可能增加待机耗电，不能保证任意电池都达到某个天数。

## 12. 蓝牙配对与槽位

BLE 1 / 2 / 3 用于区分绑定关系，不是三个同时工作的连接。切换槽位后，应确认目标电脑和槽位相匹配。长按槽位具有重新配对/清除关联的含义，应谨慎使用。

首次配对建议只让目标电脑参与。电脑忘记设备但固件还保留旧绑定，或固件清除绑定但电脑仍保留旧密钥，都可能造成重连失败；必要时两端一起清理，再重新配对。

“静默”指提示或配对流程状态，不能直接理解为射频彻底断电。多电脑热切换需要实际多机验收，本手册不声称已验证所有操作系统组合。板侧充电指示灯与蓝牙虚拟指示灯也不是一回事。

## 13. 连接状态的含义

| 层级 | 含义 | 不能证明什么 |
|---|---|---|
| 被发现 | 系统能看到设备 | 不能证明绑定成功 |
| link | 物理链路存在 | 不能证明鉴权或 RPC 就绪 |
| ready | 协议会话就绪 | 不能证明每个动作在应用内执行 |
| 按下/松开端到端成功 | 应用实际响应 | 仍需分别验证不同按键 |

开发快照中的 codex_ready 和自家 app.active 是不同状态。自家客户端未启用路由时，Codex 仍可正常工作。

## 14. 六层与路由

默认经典回退保持 Codex 控制。自家客户端连接并维持有效会话后，才启用高级路由。客户端退出或失联时必须回退，不能让用户永久卡在私有按键编号上。

第 1 层通常走 Codex；允许通过特殊映射替换部分命令。第 2～6 层可走自家客户端，也可按键透传到 Codex。编号是协议内部地址，请使用图形化配置，不要凭“第七个按键”的口头描述修改 JSON。

层循环数量可限制为常用的少数层。按住键时换层或客户端断连，需释放此前实际路由的目的键，不能只按新层发送松开。图标与路由独立，不会因为换了图标自动改变快捷键。

## 15. 键帽与单色 SVG

每层可单独选择图标，也可以使用无图标白色键帽。图标可继承默认外观，也可手动覆盖。所有输入 SVG 按单色黑色图标处理，彩色信息不作为多色键帽承诺。

新增图标资源经 USB 内容通道处理；日常已存在图标的选择与配置不同于传输整个资源库。请勿将任意带脚本、远程引用或复杂滤镜的 SVG 当作可信输入。

优先使用简洁路径、合理 viewBox 和许可清晰的图形。导入后分别检查宽键帽、普通键帽和切层后的结果。

## 16. 快捷键和 MIC 模板

管理客户端负责宿主快捷键，不要求固件理解某软件是否安装。预设仅代表按键组合，不保证软件在当前电脑注册了该快捷键。

典型包括复制、粘贴、剪切、自定义组合、Win 键、Win+H、Alt+Space、Win+Alt+Space 等。它们可能与系统或第三方工具冲突，应先在无敏感输入的窗口验证。

MIC 可用于右 Alt 模板：按下发送 keydown、松开发送 keyup；另有按下触发型需求。两者不应混淆。自定义配置必须避免只按下不松开。请用事件检测器和目标应用双重确认，而不是只看管理界面提示成功。

## 17. 灯效与所有权

外围环状灯始终跟随 Codex，不随自家客户端层号改成另一套灯效。Agent 与命令键则按当前映射显示相应状态。

Codex 路径包括 v.oai.thstatus 和 v.oai.rgbcfg 的 keys、ambient。常见枚举为 off、solid、snake、rainbow、breath、gradient、shallowBreath。协议保存颜色、亮度和速度；显示混合不等于修改原始协议值。

呼吸使用时间驱动：相同速度应具有相同相位，不应因触摸重新开始。m 为 0～1 小数，保存不代表已经证实其所有官方效果语义。

相机照片、LCD 色彩与物理 RGB 灯带不可直接逐像素比较。出现黑条时应当先排查渲染/扫描时序，而不是继续加大发光强度掩盖问题。

## 18. 音效与音量

键盘键使用预设音效；旋钮和摇杆不应当产生轴体声。左下层切换键使用独立触摸音效。音量在设置第一页调整。

若有延迟，要分别检查触摸事件、音频队列和实际播放时间。声音响了不等于主机收到了按键。调整增益可能失真，不推荐用最大音量判断普通操作响应。

## 19. 电池与充电

### 19.1 本项目使用的电池档案

1. 规格：606080 软包电芯；
2. 电芯：ATL A 类；
3. 标称电压：3.7 V；
4. 容量：4000 mAh，能量 14.8 Wh；
5. 配套带智能 IC 的保护板；
6. 固件充电配置绝对上限：1200 mA；
7. 充电截止电压：4.2 V 档，不允许用提高截止电压换取速度。

这个 1.2 A 默认值只针对上述组合。更换电池、保护板、连接器或线材后，先在 `menuconfig` 中降低 `CODEX_CHARGE_MAX_MA`，再依据新电池资料和实测恢复。保护板是故障保护，不负责替代正常充电控制。

AXP2101 的 `Ichg` 可编程范围取决于截止电压：原厂手册在 4.2 V 档列出的最大充电电流为 1.4 A；“最高可达 1.5 A”只适用于手册中的其他电压条件。本项目主动限制为 1.2 A，不写入 1.4/1.5 A 档。

### 19.2 自适应充电过程

开机先写入 200 mA 并读回寄存器。电池存在、VBUS 有效、电压与截止电压配置有效且处于恒流/恒压阶段时，按 `600 → 800 → 1000 → 1200 mA` 快速建立配置，约 30 秒完成。恒压阶段不由软件提前降到 200 mA，实际电流由 AXP2101 的恒压环路自然收尾。

低电池电压仍使用预充档。VBUS 下陷、输入限流、PMIC 热调节或遥测异常时立即降档；受限解除后先保持稳定，再恢复升档。固件不会提高输入限流来掩盖不合格供电，也不会绕过安全计时、充电终止或保护状态。

板上没有电芯 NTC，也没有可用于本项目的实际充电电流 ADC。日志中的 `charge_limit=1200mA` 是寄存器配置上限，不等于电池实时吸收 1.2 A；PMIC 结温状态不能冒充电芯温度。

### 19.3 电量、充电与功率显示

设备区分“无电池”和“有电池”。无电池时设备显示 `No battery`，为兼容宿主可对外报告 100%；有电池时必须返回 E-gauge/电压状态，不能固定为 100%。外接 USB 表示 VBUS 存在，不必然表示电池正在充电或仍以恒流充电。

UI 中的功率是根据配置上限估算，不是功率计读数。Windows 的电量显示还可能受 BLE Battery Service 缓存影响，应分别核对设备日志、系统界面和外部 USB 功率计。

### 19.4 3–4 小时目标的验收

4000 mAh 电池从 10% 到 100% 理论上至少需要补入约 3600 mAh。要验证 3–4 小时目标，应从低于 10% 开始，记录开始/结束时间、每十分钟的电量、电压、阶段、VBUS、限制状态和异常，并用 USB 功率计记录实际输入。满电时仅观察到“1200 mA 配置保持”不能证明恒流阶段真实持续 1.2 A。

## 20. 屏保与智能屏保

普通屏保按设备的闲置策略计时，Codex App 的自动调暗控制灯效，不直接等于设备屏保设置。

智能屏保开启时应结合灯光活动：有有效灯光状态或操作时保持显示并重置空闲计时；长期全灭后才按配置进入屏保。不能用呼吸周期瞬间最暗的一帧判定长期闲置。

真正息屏要求背光关闭，而非画面刷黑、亮度降至最低。当前仍需暗室复核用户报告的偶发微亮问题；软件 power=Screensaver 和全黑截图均不是物理关断证明。

## 21. 受保护待机

该模式避免误触。唤起解锁页不等于解除保护，需完成滑动解锁；超时则重新隐藏。不要将解锁页出现时的临时点亮当作异常自动唤醒。

出现解锁拖不动时记录触点与 UI 状态，不能用反复重启代替定位。退出后应确认所有此前按下的控制已释放。

## 22. Ultra 与自动关机

优先级为：**关机 > Ultra standby > Connected standby / 屏保**。

Connected standby 保留会话，Ultra 主动断开后深度休眠，关机由电源路径处理。唤醒后需要给系统重新枚举/重连的时间。深待机不能同时承诺“无线完全不工作”与“BLE 永不掉线”。

自动关机条件与无人操作、无连接及防误触开关有关；关闭某个定时器不等于禁用其他定时器。配置后建议先以较短时间验证，再恢复日常值。日志中的单调运行时间与重启后的时间不可混算。

## 23. Arcade

Arcade 是可选特殊界面，不是独立游戏主机。触发能否在 Codex 中成功取决于宿主版本与状态。界面包含 Agent 发射键和放大的方向控制，可切换方向操作方式，通过右上关闭返回经典模式。

经典摇杆灵敏度不应套用到 Arcade。进入或退出后应确认 MIC/方向/按键没有滞留。不要把游戏触发动画运行完成当作宿主已进入游戏的确认。

## 26. 烧录与恢复

```sh

```

YOUR_UART_PORT 替换为实际端口；Windows 如 COM5，Linux 如 /dev/ttyACM0 或 /dev/ttyUSB0，以枚举为准。

## 30. 开发诊断接口


## 31. 截图方法与限制

screen read 返回 RGB565 的十六进制像素。单次最多 1024 像素，整屏截图须分块，避免持续大范围读取抢占显示带宽。

按每行像素解析：R=(v>>11)&31，G=(v>>5)&63，B=v&31，再缩放到 8 位颜色。保留采集时间、固件版本与原始记录，图中不得混入未经说明的桌面模拟内容。

截图能验证布局、文字与帧缓冲内容，**不能验证背光电气关断、扫描途中撕裂、触摸延迟或亮度闪烁**。这些需要同步视频/光学测量及日志。禁止将模拟灯效截图冒充真实宿主下发。

## 33. 故障排查

### 无串口

先核对 USB TO UART 标识和数据线，再检查设备枚举。原生 HID 没有 COM 是可能正常的。不要仅根据供电绿灯断言数据线正常。

### Codex 功能受限/连接中断

区分系统配对、BLE ready、Codex RPC 和管理 app 会话。记录断连时间、原因及应用版本。不要立即清空所有设置，也不要同时运行多个争抢设备的重映射工具。

### 屏幕全黑

区分待机、Ultra、关机、下载模式和故障。先查看 UART 状态，不要盲目反复写入其他固件。

### 息屏仍有微光

在暗室判断整个背光是否发光；侧边充电 LED 反射也应区分。记录是 PWR、自动屏保还是保护待机触发，屏保前亮度、供电方式、唤醒次数和日志。本问题未通过物理验收前不得标记已解决。

### 黑块/撕裂

保存视频与准确时间；屏幕缓存正常不排除 RGB 扫描/DMA 时序异常。不要提高日志和截图频率到反过来影响扫描。

### 电量不一致

比较设备电池存在位、百分比、电压、充电标志和 Windows 缓存。无电池兼容 100% 与真实电池 100% 必须分清。

### MIC 松开后仍录音

检查真实 release 事件、传输结果和应用录音状态。没有新触摸坐标不代表手指已离开，不能用固定短时限把静止长按强制释放。

## 37. 逐个控件操作参考

本章按“你实际会看到和碰到的控件”逐项说明。先记住三个原则：

1. **键帽图标与按键动作互相独立。** 换图标只改变画面，不会自动改变事件或快捷键。
2. **Codex 通道与自家客户端通道互相独立。** 默认第 1 层交给 Codex；高级映射只有在 Codex Micro Control 已连接并维持有效会话时生效。
3. **看到动画不等于电脑已执行。** 重要动作，尤其 MIC 的按住/松开，应以电脑端实际响应为准。

### 37.1 经典界面的六个 Agent 键

六个半透明发光键依次对应 `AG00`～`AG05`。

| 操作 | 结果 |
|---|---|
| 点按 | 向当前路由目标发送该 Agent 键的按下与松开事件 |
| 按住 | 保持按下状态，松手时发送释放；通常不应当把它当成连续重复键 |
| Codex 返回状态 | 固件根据 `v.oai.thstatus` 显示该键的颜色和灯效 |
| 自家客户端未连接 | 使用经典回退路由，保持原有 Codex 行为 |
| 高级路由启用 | 第 2～6 层可交给客户端，也可逐键透传回 Codex |

Agent 键的颜色由状态决定，不是触摸后永久点亮。没有收到有效状态时应保持默认熄灭外观。相同速度的 `breath` 使用同一全局时间相位，所以稍后加入的键会直接加入当前明暗节奏。

### 37.2 六个命令键

默认图标依次为闪电、勾选、叉号、Computer Use、MIC 和 Codex；MIC 是横向两格宽键。协议上它们是命令控件，图标不是不可更改的功能标签。

| 默认键帽 | 默认用途提示 | 操作方法 | 注意事项 |
|---|---|---|---|
| 闪电 | 快捷动作 | 点按 | 最终含义由 Codex 或客户端映射决定 |
| 勾选 | 接受/确认 | 点按 | 不要仅凭图标假定某个弹窗一定会被批准 |
| 叉号 | 拒绝/取消 | 点按 | 最终行为取决于当前宿主映射 |
| Computer Use | 计算机操作入口 | 点按 | 不是固件直接控制 Windows 鼠标 |
| MIC | 语音 | **按下并保持，完成后松开** | 按下和释放都是 P0 事件；松手后应确认电脑停止录音 |
| Codex | Codex 入口 | 点按 | 可由桌面客户端改成前台切换或其他动作 |

普通命令键使用当前轴体音效预设；MIC 同样产生按下/松开事件。若客户端把 MIC 改为 Typeless“按住说话”，按下发送 Right Alt keydown，松开发送 Right Alt keyup；“点按切换”模板则只在按下时触发一次，两种模板不能混用。

### 37.3 左上旋钮

| 手势 | 设备上报 |
|---|---|
| 顺时针旋转 | `ENC_CW` |
| 逆时针旋转 | `ENC_CCW` |
| 不旋转时点按 | `ENC` 单击 |
| 不旋转并持续按住 | 旋钮长按 |

旋转期间的位移优先解释为旋转，不应误判为长按。固件只报告控件事件，浏览、选择或打开设置等具体含义由宿主应用配置。

### 37.4 右上摇杆

把摇杆从中心向任意方向拖动即可产生方向和幅度事件，松手回中。它不播放键盘轴体声。

经典模式的灵敏度可在设置第二页调整：数值越高，相同拖动距离产生的输出越大。Arcade 模式使用自己的控制尺度，不受经典摇杆灵敏度影响。轻微触碰没有反应时，先排除中心死区，不要直接把它判断为断连。

### 37.5 左下层切换触摸键与三颗指示灯

短按左下圆形触摸键切换到下一层；达到所设循环层数后回到第 1 层。该键使用独立的“擦声”，不使用机械轴体声音。

三颗小灯只表示当前层，不表示电量、蓝牙信号或 Agent 状态。默认可循环六层；客户端可将循环范围限制为 2 层或 3 层。图标可以每层不同，但只有客户端会话有效时，高层自定义路由才生效；客户端失联后回退到经典 Codex 路由。

### 37.6 PWR 侧键

| 操作 | 结果 |
|---|---|
| 短按 | 按设置第三页的选择进入 Connected standby 或 Ultra standby |
| 待机时再次短按 | 唤醒并恢复正常界面 |
| 长按 | 请求板载 PMIC 关机 |
| 关机后长按 | 由板载电源路径重新开机，具体表现以实际硬件为准 |

Connected standby 关闭显示和背光，但维持 USB/BLE 会话；Ultra 主动进入更深省电状态，通信会断开，唤醒后重新连接。PWR 短按不是普通屏幕按键，不能用 UI 动画代替硬件背光关断。

### 37.7 BOOT 侧键

| 场景 | 操作与结果 |
|---|---|
| 固件正常运行 | 短按打开或关闭设置中心 |
| 当前 BLE 槽位 | 长按进入重新配对/清除当前绑定流程 |
| 设备断电 | **按住 BOOT 再上电**进入 ESP32-S3 ROM 下载模式 |

ROM 下载路径是救砖入口。不要断开 BOOT 与 GPIO0，也不要让 BOOT 在每次上电时永久处于按下状态。

### 37.8 设置中心通用控件

设置中心共三页，使用底部 **Previous / Next** 点击换页；底部圆点显示当前页。这里不使用横向拖页。关闭按钮返回经典界面。

滑块应点击或拖动滑块轨道；点击功能按钮后要等待文字或选中态更新。设备正在写入 NVS 时不要突然断电。

### 37.9 设置第一页：连接、槽位、电池与声音

| 控件 | 怎么用 | 会发生什么 |
|---|---|---|
| AUTO | 点按 | 自动选择可用通信路径，通常优先已有可用链路 |
| USB | 点按 | 仅使用原生 USB 日常通信；USB TO UART 仍用于刷写/日志 |
| BLE | 点按 | 仅使用当前蓝牙槽位 |
| MIX | 点按 | 同时允许 USB 与 BLE；便利但通常更耗电 |
| BLE 1 / 2 / 3 | 短按某个槽位 | 热切换到该槽位保存的绑定关系 |
| BLE 1 / 2 / 3 | 长按当前槽位 | 清除该槽绑定并进入约 20 秒可配对状态 |
| Bluetooth | 点按 | 开启或关闭蓝牙射频与 BLE 日常连接 |
| Clear bonds | 点按 | 清除保存的蓝牙绑定；电脑端通常也需要“忘记设备” |
| Volume | 拖动 | 调整键盘音效音量；左下触摸擦声仍使用独立素材 |
| 电池卡片 | 只读 | 显示电池百分比、充电/放电/USB 状态和估算信息 |
| 连接指示 | 只读 | 绿色表示协议已就绪；系统“已连接”不一定等于这里已就绪 |

槽位应理解为三套持久化 peer/bond 资料，而不是三个同时工作的 BLE 连接。切换成功后，目标主机会自动重连；长按重置会破坏该槽原绑定。设备侧虚拟蓝牙指示会在配对时闪烁、连接成功后短时常亮，再回归普通显示。

无电池时设备显示 `No battery`；兼容宿主可能看到 100%。有电池时必须显示真实估算值。插着 USB 只证明 VBUS 存在，不自动等于正在向电池充电。

### 37.10 设置第二页：显示、计时和特殊模式

| 控件 | 怎么用 | 含义 |
|---|---|---|
| Screen brightness | 拖动，十档 | 调整正常亮屏亮度；最低 10% 不是息屏 |
| Joystick sensitivity | 拖动 | 调整经典模式摇杆响应，Arcade 不受影响 |
| Screen | 连续点按 | 在关闭、30 秒、1、3、10、30 分钟和 1 小时之间循环 |
| Auto shutdown | 连续点按 | 选择自动关机时间；命中后需重新开机 |
| Smart screensaver | 点按开/关 | 只有灯效全灭且无操作持续到 Screen 时间才息屏；任意灯亮或触控会重新计时 |
| Anti-accidental shutdown | 点按开/关 | 开启后自动关机主要依据链路状态，不让零星触控无限推迟关机 |
| Protected standby | 点按 | 立即进入防误触待机 |
| Arcade trigger | 点按 | 自动生成满足 Codex 彩蛋条件的摇杆轨迹并进入 Arcade |
| Firmware version | 只读 | 显示当前设备固件版本 |

自动关机优先级高于 Ultra，Ultra 高于 Screen/Connected standby。高优先级计时不会因为较低优先级先触发而重复冲突。

### 37.11 受保护待机解锁页

进入后正常界面停止绘制。按任意侧键，或在 1.5 秒内连续触摸屏幕两次，可临时显示解锁页。把宽圆角滑块从起点拖到另一端才会退出保护；只点一下或拖动不足不会退出。解锁页约 3 秒无操作会重新黑屏。

### 37.12 设置第三页：深度省电

| 控件 | 怎么用 | 含义 |
|---|---|---|
| PWR: Connected standby / Ultra standby | 点按切换 | 决定 PWR 短按进入哪种待机 |
| Auto ultra | 连续点按 | 在关闭、1、3、5、8、12 小时之间选择自动深待机 |
| Ultra touch wake | 点按开/关 | 开启后 Ultra 可保留触摸唤醒；会增加待机耗电 |

如果希望 Codex 会话不断开，应使用 Connected standby。Ultra 无法在保持 BLE 握手的同时实现同等级深睡功耗；客户端应将这种主动睡眠识别为预期断开，唤醒后再重连。

### 37.13 电池告警弹窗

电量低于 10%，或从“已连接电池”变为“未检测到电池”时出现告警。点击 **知道了/Acknowledge** 关闭；不处理时最长保留约 600 秒。告警不代表充电器一定故障，应结合电池状态、VBUS 和 UART 日志判断。

### 37.14 Arcade 界面控件

| 控件 | 怎么用 |
|---|---|
| AG00 | 发射；事件与经典界面的 AG00 一致 |
| 大摇杆 | 控制 Asteroids 移动 |
| 使用十字键 | 切换为分体方向键 |
| 使用触控区域 | 切换为手游式虚拟移动区域 |
| 右上角 X | 退出 Arcade，显示过渡页后回到经典界面 |

Arcade 只替换当前界面，不应改变 Codex 外围灯的所有权。退出失败时不要反复高速点击，应通过 UART 日志确认触摸事件和模式状态。

### 37.15 Windows 客户端：DEVICE 页面

| 控件 | 怎么用 |
|---|---|
| USB / Bluetooth LE | 选择连接传输 |
| Connect | 连接设备并读取能力、状态与持久化配置 |
| Disconnect | 主动结束自家客户端会话；固件回退到经典 Codex 路由 |
| Refresh/重新读取 | 重新获取状态，不会替代重新配对 |
| 设备预览 | 展示当前层、图标和状态；它是预览，不是触摸遥控器 |

USB 高级配置要求原生 USB 数据线；USB TO UART 串口不能自动替代配置协议。客户端的“已连接”只代表自家通道，不代表 Codex App 同时完成握手。

### 37.16 Windows 客户端：KEYS & LAYERS 页面

1. 先选择顶部的 Layer 1～6。
2. 在设备预览中点击要编辑的键帽。
3. 在路由编辑器选择 **Codex 原生、客户端动作或禁用**。
4. 若选择客户端动作，再选择预设或自定义组合键。
5. 单独选择键帽图标；路由与图标不会彼此自动修改。
6. 保存配置。客户端会话有效时运行高级路由；断连后固件自动回退。

第 1 层的替换动作使用独立影子路由标识，不会误改第 2～6 层相同物理位置。高层按键也可以明确透传到第 1 层 Codex 控件。Layer 1 的 Agent 键保持交给 Codex；可替换范围以页面实际允许选择的键为准。

| 预设 | 实际输出/行为 |
|---|---|
| 复制 / 粘贴 / 剪切 | Ctrl+C / Ctrl+V / Ctrl+X |
| Windows 键 | Win |
| Click to Do | Win+Q；只提供快捷键，不检查电脑是否支持 |
| 打开 Codex / ChatGPT | 请求客户端把对应程序切到前台 |
| 窗口置顶 | Win+Ctrl+T，预期由 PowerToys 接收 |
| Typeless | Alt+Space |
| Typeless 按住说话 | Right Alt 按下/松开成对发送 |
| Typeless 点按切换 | 按下时触发一次 Right Alt |
| 微软语音输入 | Win+H |

预设不检查对应软件是否安装。第一次测试自定义组合时，请在空白文本编辑器和按键事件检测器中验证，避免在有删除、发送或付款动作的窗口中试键。

### 37.17 图标选择与自定义 SVG

点击图标库中的图标即可用于当前层当前键；选择空白项会显示无图标白色键帽。导入自定义 SVG 时：

- 只接受单色图形，所有颜色按黑色处理；
- 图标与动作完全解耦；
- 新增图标内容通过 USB 传输，不通过 BLE 发送大资源；
- 导入后仍需点击保存；
- 复杂滤镜、脚本、外链和不合理尺寸会被拒绝。

### 37.18 Windows 客户端：SETTINGS 页面

| 控件 | 作用 |
|---|---|
| 连接模式 | 写入 AUTO、USB、BLE 或 Mixed 偏好 |
| Bluetooth radio | 开关设备蓝牙 |
| BLE 1 / 2 / 3 | 切换活动槽位 |
| 屏幕亮度 | 调整正常界面亮度 |
| 音量与轴体预设 | 选择 Linear、Tactile 或 Clicky，并调整音量 |

| 控件 | 作用 |
|---|---|
| Check/检查 | 查询客户端和设备可用更新 |

开源仓库不硬编码作者的私有更新域名，也不提供公共更新服务或 Release 包。因此自行构建版本即使显示这些控件，也只有在维护者自行配置兼容服务、签名材料和更新元数据后才能完成联网更新。固件和图标内容更新只允许 USB；BLE 仅用于轻量管理。

### 37.20 “按钮没反应”时按这个顺序检查

1. 看设备是否只是亮屏，还是自家客户端会话真的为 Ready。
2. 确认当前层；高层在客户端失联时会回退到经典路由。
3. 确认改的是“动作”而不只是“图标”。
4. MIC 必须同时验证按下和松开。
5. BLE 槽位不匹配时，在电脑和对应槽位两端清理旧绑定。
6. USB 配置失败时确认插的是原生 USB 数据口，而非只有 UART 日志的口。
7. 仍失败时收集 UART 复位原因、连接状态、请求 ID 和客户端日志，再提交问题。
